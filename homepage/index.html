Why teams choose it

不是临时转发脚本，而是 Sealos 场景里的隧道控制面。

01

更少云端配置

CLI 自动创建远端代理 Pod、Service 和 Ingress。你只需要确认本地端口，Sealtun 负责把它变成可访问的 HTTPS 入口。

02

更稳的域名路径

先生成 Sealos 官方子域名，再引导 CNAME 到该地址；自定义域名绑定前会验证 DNS，绑定后能诊断证书和 Ingress 状态。

03

更清楚的本地状态

Profile、region、workspace 和 kubeconfig 都跟随 active scope。CLI 与 dashboard 只读取当前 Sealtun 配置边界内的数据。

Product capabilities

从暴露端口到排障闭环，常用能力已经连成一条线。

适合开发预览、临时验收、客户演示、Webhook 回调、本地调试和团队联调。

EX

Expose

sealtun expose 3000 创建公网 HTTPS 地址，并由本地 daemon 维护连接。

DM

Custom domain

domain status 和 domain doctor 检查 CNAME、Ingress、Certificate 与 TLS secret。

PF

Profile & region

多账号、多 region、多 workspace 分开保存，切换 profile 时同步切换 auth 与 kubeconfig。

AP

Declarative apply

sealtun apply -f sealtun.yaml 用稳定名称幂等创建或更新团队共享隧道。

Operational workflow

一条清晰路径，覆盖创建、连接、观察和回收。

Login

选择区域与身份

登录获取 Sealos Cloud 凭据，保存当前 region 的 kubeconfig 与可用域名后缀。

Provision

创建云端代理

远端资源按 sealtun-* 命名，便于诊断、审计和安全清理。

Connect

建立反向隧道

本地 daemon 连接远端 WebSocket 控制面，并把请求转发到本地服务。

Observe

诊断和观测

inspect、doctor、logs、metrics 与 dashboard 形成排障闭环。

Local dashboard

给运营和排障留一个可读的本地视图。

Dashboard 只读取 ~/.sealtun 当前登录范围内的数据，展示隧道、域名、诊断和运行状态，不越界扫描系统配置。

Install

下载一个二进制，就能开始创建 Sealos 隧道。

GitHub Releases 提供 macOS、Linux 和 Windows 产物。正式发布时，远端 Pod 镜像与 CLI 版本保持一致。

OS="$(uname -s | tr '[:upper:]' '[:lower:]')"
ARCH="$(uname -m)"
case "$ARCH" in
  x86_64) ARCH="amd64" ;;
  arm64|aarch64) ARCH="arm64" ;;
esac
curl -L "https://github.com/gitlayzer/sealtun/releases/latest/download/sealtun_${OS}_${ARCH}.tar.gz" -o sealtun.tar.gz
tar -xzf sealtun.tar.gz sealtun
chmod +x sealtun
sudo mv sealtun /usr/local/bin/sealtun
$arch = if ([System.Runtime.InteropServices.RuntimeInformation]::OSArchitecture -eq "Arm64") { "arm64" } else { "amd64" }
Invoke-WebRequest -Uri "https://github.com/gitlayzer/sealtun/releases/latest/download/sealtun_windows_$arch.zip" -OutFile sealtun.zip
Expand-Archive .\sealtun.zip -DestinationPath .
.\sealtun.exe --version
git clone https://github.com/gitlayzer/sealtun.git
cd sealtun
make build
./sealtun --version
