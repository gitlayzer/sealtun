v0.0.15 · Sealos native tunnel

把本地服务发布成可控、可诊断的 Sealos 公网入口。

Sealtun 不只是把端口转出去。它会创建 Kubernetes 代理资源，保留 Sealos 控制面域名，处理自定义域名和证书诊断，并把 Basic Auth、Bearer Token、IP 规则、临时链接这些访问策略放在代理层执行。

Access policy

公网预览不应该只有“能访问”和“不能访问”。

现在可以在创建隧道时直接定义访问边界。Sealtun 把认证和 IP 规则放在 server proxy 层，不依赖 Ingress annotation，也不会把 token 明文塞进 Deployment 参数。

一次暴露，带上访问规则

Basic Auth 适合给客户或同事临时访问；Bearer Token 适合 Webhook、机器人回调和自动化测试；临时链接可以给验收和审查留一个明确过期时间。

  • Basic Auth、Bearer Token、临时 token 支持环境变量读取。
  • IP allowlist / denylist 支持单个 IP 和 CIDR。
  • 临时链接参数会在转发到本地服务前移除。

How it works

从本地端口到稳定入口，路径保持清楚。

01

登录和 Profile

设备授权登录，保存 region、workspace、auth 和 kubeconfig。多账号场景用 profile 隔离。

02

创建远端代理

使用 Kubernetes API 创建 `sealtun-*` Deployment、Service 和 Ingress，等待远端 Pod ready。

03

连接本地 daemon

daemon 维护 WebSocket + yamux 反向隧道，把公网请求转发到 `localhost:3000`。

04

观测和回收

`list`、`inspect`、`doctor`、`logs`、`metrics`、`dashboard` 负责看清状态，`stop` 和 `cleanup` 负责回收。

Observe

问题发生时，不需要从 YAML 和控制台里猜。

自定义域名会先验证 CNAME 归属，再写入 Ingress 和 cert-manager 资源。Dashboard、logs、metrics 和 doctor 则把本地 session、远端 Pod、Ingress、证书、Event 放在同一条排障路径里。

Declarative config

把团队共享入口写进 `sealtun.yaml`。

`apply --dry-run` 可以离线预览，`diff -f` 对比本地 session 和目标配置，真正 apply 时用稳定 name 更新同一个隧道。`ttl` 会写入本地 session，到期后 daemon 自动清理远端资源。

version: v1
tunnels:
  - name: web
    localPort: 3000
    protocol: https
    domain: app.example.com
    ttl: 2h
    accessPolicy:
      bearerTokenEnv: SEALTUN_BEARER_TOKEN
      temporaryLinks:
        - name: review
          tokenEnv: SEALTUN_TEMP_TOKEN
          ttl: 1h

Install

从 npm、npx 或 Release 二进制开始。

npm 包会按当前系统安装对应平台的可选二进制依赖；正式 Release 会同步 GitHub 资产和 `ghcr.io/gitlayzer/sealtun` 远端镜像。
