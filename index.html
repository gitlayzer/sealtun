Controlled localhost tunnels for Sealos.

What it does

从本地服务到公网入口，保持短路径和可控边界。

01

直接生成 Sealos 原生入口

登录后暴露本地端口，远端使用 Kubernetes 资源承载隧道代理，生成可访问的 HTTPS 地址。

02

访问策略在代理层执行

Basic Auth、Bearer Token、IP allowlist / denylist 和临时链接都在 Sealtun proxy 层生效，避免把业务访问边界交给人工约定。

03

声明式配置和诊断可以复用

sealtun.yaml 支持 dry-run、diff 和 apply；doctor、logs、metrics、dashboard 让问题定位回到同一条链路。

Codex Skill

让 agent 会用 Sealtun，也知道什么时候不该动手。

仓库内置 skills/sealtun，覆盖隧道使用、访问控制、声明式配置、排障和发布流程。它会先判断任务边界；涉及 expose、apply、git push、npm publish 这类会改变状态的操作时，不会跳过确认。

Install

一个 CLI，覆盖临时演示、回调调试和团队联调。

从 npm 或 npx 开始；需要团队共享时，把隧道写进 sealtun.yaml，用 dry-run 和 diff 先看清变更。

npm install -g sealtun
sealtun login gzg --profile demo
sealtun expose 3000
export SEALTUN_BASIC_AUTH_PASSWORD='change-me'
export SEALTUN_TEMP_TOKEN='review-link-secret'

sealtun expose 3000 \
  --basic-auth-user admin \
  --basic-auth-password-env SEALTUN_BASIC_AUTH_PASSWORD \
  --temporary-access-token-env SEALTUN_TEMP_TOKEN \
  --temporary-access-ttl 1h
sealtun apply -f sealtun.yaml --dry-run
sealtun diff -f sealtun.yaml
sealtun apply -f sealtun.yaml

sealtun doctor
sealtun cleanup
