What Sealtun does

从本地端口到公网入口，路径应该短，边界应该清楚。

Sealtun 使用 Sealos Cloud 的 Kubernetes、Service 与 Ingress 能力，把本地服务通过加密 WebSocket 隧道转发出去。开发预览、第三方回调、SSH 调试、数据库临时访问和团队评审链接，都可以走同一套 CLI。

Public entrances

不同协议有不同入口，不混在一起。

HTTPS 适合 Web 和回调，SSH/TCP 走四层公网 NodePort。访问控制、临时分享和自定义域名属于 HTTPS 代理层能力，规则清楚，排障也更直接。

01

HTTPS 预览

一条 `sealtun expose 3000` 获得受信任的公网 URL，兼容普通 HTTP 和 WebSocket 应用流量。

sealtun expose 3000
02

公网 SSH

本地 sshd 可以通过 `--protocol ssh` 暴露成公网 TCP 入口，适合临时调试机器或开发环境。

sealtun expose 22 --protocol ssh
03

通用 TCP

Postgres、Redis、MQTT 或其他非 HTTP 服务可以走 `--protocol tcp`，输出公网 host 和 port。

sealtun expose 5432 --protocol tcp

Latest capabilities

最新功能已经覆盖域名、分享、诊断、工作台和配置回收。

Domains

域名先 plan，再 add、verify 和 doctor

`domain plan` 先生成 CNAME 指引，`domain add --wait` 等待 DNS 和证书就绪，`domain doctor` 用来串起 Ingress 与证书状态。

domain plan domain add --wait domain doctor
Share

已有 HTTPS 隧道可以临时分享

`share create/list/revoke` 生成自动失效的评审链接，URL 只在创建时显示一次，后续列表不泄漏 token。

Access policy

访问策略在代理层执行

Basic Auth、Bearer Token、临时 token、IP allowlist 和 denylist 都由 Sealtun proxy 校验，不依赖 Ingress annotation。

Workbench

Dashboard 是本地工作台

可以创建 HTTPS/SSH/TCP 隧道，执行 YAML dry-run/diff/apply，查看 logs、metrics、events，并管理 domain、stop/start/cleanup。

YAML

模板、apply 和 export 可以闭环

`template` 生成命令和 `sealtun.yaml`，`apply` 用稳定名称幂等创建或更新，`export --all` 把本地 session 安全回收成 YAML。

Diagnostics

单条隧道诊断更直接

`doctor `、`inspect --remote`、logs、events 和 metrics 会把本地 daemon、远端 Pod、Service、Ingress 与证书问题串起来。

Codex Skill

不用先学 Sealtun，让 AI 先学会。

通过一条 npx 命令把仓库里的 Skill 装进 AI 工作流。之后你可以直接描述目标，比如暴露本地服务、加认证、创建临时分享、绑定域名、导出 sealtun.yaml 或跑 doctor。

npx skills add https://github.com/gitlayzer/sealtun
01安装 Skill，让 AI 知道 Sealtun 的 CLI、YAML 和安全边界。
02用自然语言描述端口、协议、域名和访问规则。
03涉及 expose、apply、domain、cleanup 等状态变更时先确认。
04让 AI 处理命令细节、诊断输出和后续配置整理。

Install and operate

AI 用 Skill，人用 CLI，团队用 sealtun.yaml。

安装路径保持短，运行路径保持可审计。你可以临时用 npx，也可以全局安装 CLI；团队配置写进 YAML 后再 dry-run、diff、apply。

npx skills add https://github.com/gitlayzer/sealtun

# Then ask your AI agent:
# Expose localhost:3000, add Basic Auth,
# create a review share, then export sealtun.yaml.
npm install -g sealtun
sealtun login gzg --profile demo

sealtun expose 3000
sealtun expose 22 --protocol ssh
sealtun expose 5432 --protocol tcp
sealtun expose 3000 --domain app.example.com

sealtun domain plan <tunnel-id> app.example.com
sealtun domain add <tunnel-id> app.example.com --wait
sealtun domain verify <tunnel-id> --wait --timeout 5m
sealtun domain doctor <tunnel-id>
export SEALTUN_BASIC_AUTH_PASSWORD='change-me'
sealtun expose 3000 \
  --basic-auth-user admin \
  --basic-auth-password-env SEALTUN_BASIC_AUTH_PASSWORD

sealtun share create <tunnel-id> --name review --ttl 2h
sealtun share list <tunnel-id>
sealtun share revoke <tunnel-id> review
sealtun template https --name web --port 3000
sealtun template postgres --name db
sealtun export --all -o sealtun.yaml
sealtun export --all --include-secret-placeholders

sealtun apply -f sealtun.yaml --dry-run
sealtun diff -f sealtun.yaml
sealtun apply -f sealtun.yaml
