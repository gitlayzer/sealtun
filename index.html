What changed

它现在更像一个隧道控制面，而不是临时端口转发。

Sealtun 会创建 Kubernetes 原生资源，保留 Sealos 控制面域名，把公网访问策略放在代理层执行，并提供 CLI、Dashboard、声明式配置和 Skill 给人和 agent 使用。

01

访问策略不依赖 Ingress annotation

Basic Auth、Bearer Token、IP allowlist / denylist、临时链接都在 Sealtun server proxy 层执行。公网业务路径受保护，控制通道和健康检查不会被误拦截。

02

自定义域名先验证，再绑定

先生成 Sealos host 作为 CNAME 目标。CNAME 归属验证通过后，才写入 Ingress 并管理 cert-manager 证书，避免未验证域名被提前占用。

03

声明式隧道可以 diff 和 dry-run

sealtun apply -f sealtun.yaml --dry-run 离线预览，sealtun diff -f 对比本地 session，真实 apply 使用稳定 name 更新同一条隧道。

04

观测路径完整

list、inspect、doctor、logs、metrics、dashboard 把本地 daemon、远端 Pod、Ingress、证书和 Event 放到一条排障路径里。

Codex Skill

让 AI agent 先判断任务，再决定怎么操作 Sealtun。

仓库内置 skills/sealtun，会识别内网穿透、临时公网预览、Webhook 回调、访问控制、sealtun.yaml、诊断和 npm 发布等场景。没有明确要求时，它不会擅自运行 expose、apply、domain set、git push 或 npm publish。

内网穿透 Webhook 回调 临时公网地址 隧道访问控制 npm 发布

Workflow

从登录到回收，每一步都有清楚边界。

Login

选择 region 和 profile

设备授权登录，保存 region、workspace、auth 和 kubeconfig。多账号场景用 profile 隔离。

Expose

创建 Sealos 原生资源

远端资源按 `sealtun-*` 命名，使用 Deployment、Service、Ingress 和同版本镜像。

Secure

加上公网访问边界

把认证、IP 规则和临时访问时间写进隧道配置，而不是留给人工约定。

Observe

诊断、日志、指标和清理

Dashboard 只监听本地地址；doctor 汇总本地和远端状态；TTL 到期后 daemon 清理资源。

Observe

本地控制台和 CLI 命令读同一份状态。

Dashboard、logs、metrics、domain doctor 共同覆盖本地 session、远端 Pod、Ingress、证书和请求计数。排障时不用在多个控制台之间猜。

Install

用 npm、npx 或 Release 二进制开始。

npm 包会按当前系统安装对应平台的可选二进制依赖；Release 会同步 GitHub 资产和 ghcr.io/gitlayzer/sealtun 远端镜像。

npm install -g sealtun
sealtun --version

npx sealtun@latest login
sealtun expose 3000
export SEALTUN_BASIC_AUTH_PASSWORD='change-me'
export SEALTUN_TEMP_TOKEN='review-link-secret'

sealtun expose 3000 \
  --basic-auth-user admin \
  --basic-auth-password-env SEALTUN_BASIC_AUTH_PASSWORD \
  --temporary-access-token-env SEALTUN_TEMP_TOKEN \
  --temporary-access-ttl 1h
sealtun apply -f sealtun.yaml --dry-run
sealtun diff -f sealtun.yaml
sealtun apply -f sealtun.yaml

sealtun dashboard
sealtun doctor
