Sealos Cloud Native Tunnel

把本地服务变成可信公网入口。

Sealtun 用 Kubernetes 原生资源和 WebSocket 多路复用隧道，把本地开发服务安全暴露到公网。它不是临时脚本，而是一套面向 Sealos Cloud 的隧道控制面。

Why Sealtun

为 Sealos 使用场景设计，而不是泛泛的端口转发。

Sealtun 直接理解 region、workspace、kubeconfig、Ingress 域名和 cert-manager 证书状态。它把复杂的云端资源管理压缩成稳定的 CLI 工作流。

01

一条命令暴露本地服务

执行 sealtun expose 3000，自动创建远端代理 Pod、Service 和 Ingress，并连接回本地端口。

02

自定义域名可诊断

先生成 Sealos 官方子域名，再要求用户 CNAME 到该 host。domain doctor 会检查 DNS、Ingress、Certificate 和 TLS secret。

03

多账号与多 region

Profile 保存 auth、region、workspace 和 kubeconfig。切换 profile 后，CLI 和 dashboard 都只读取当前 active scope。

04

声明式配置

sealtun apply -f sealtun.yaml 使用稳定名称幂等创建或更新隧道，适合团队沉淀开发入口。

Operational Path

从本地端口到可信公网域名，路径清晰可回收。

Login

选择 region 和 profile

登录会保存当前 region 的 kubeconfig 与 `SEALOS_DOMAIN`，后续资源都落在对应 workspace。

Provision

创建云端隧道代理

CLI 通过 Kubernetes API 创建 `sealtun-*` 资源，并等待远端 Deployment ready。

Connect

daemon 维护 WebSocket 隧道

本地 daemon 会持续连接远端 `/_sealtun/ws`，并把公网请求转发到 `localhost`。

Observe

诊断、日志、指标和清理

`inspect --remote`、`doctor`、`logs`、`metrics` 和 dashboard 组成完整的诊断闭环。

Install

一个二进制，客户端和远端 server 共用。

GitHub Releases 提供 macOS、Linux 和 Windows 多平台产物。远端 Pod 使用同版本 GHCR 镜像，版本链路清晰。

OS="$(uname -s | tr '[:upper:]' '[:lower:]')"
ARCH="$(uname -m)"
case "$ARCH" in
  x86_64) ARCH="amd64" ;;
  arm64|aarch64) ARCH="arm64" ;;
esac
curl -L "https://github.com/gitlayzer/sealtun/releases/latest/download/sealtun_${OS}_${ARCH}.tar.gz" -o sealtun.tar.gz
tar -xzf sealtun.tar.gz sealtun
chmod +x sealtun
sudo mv sealtun /usr/local/bin/sealtun
$arch = if ([System.Runtime.InteropServices.RuntimeInformation]::OSArchitecture -eq "Arm64") { "arm64" } else { "amd64" }
Invoke-WebRequest -Uri "https://github.com/gitlayzer/sealtun/releases/latest/download/sealtun_windows_$arch.zip" -OutFile sealtun.zip
Expand-Archive .\sealtun.zip -DestinationPath .
.\sealtun.exe --version
git clone https://github.com/gitlayzer/sealtun.git
cd sealtun
make build
./sealtun --version
